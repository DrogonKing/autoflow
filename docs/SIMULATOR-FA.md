# میدان تست — برای امتحان کردن افزونه بدون ریسک

صفحه‌ای که خودش هر کلیک را با **زمان صدم ثانیه** ثبت می‌کند، تا ببینی افزونه واقعاً کجا و چه زمانی کلیک کرده.

---

## راه انداختن — ساده‌ترین راه

فایل **`autofook-test-field.html`** را بگیر و **دوبار کلیک کن**. همین.

- سرور لازم ندارد
- اینترنت لازم ندارد
- یک فایل تنها، ۱۱ کیلوبایت
- در همان مرورگری بازش کن که افزونه در آن نصب است (کروم/Edge)

**اگر افزونه روی این صفحه کار نکرد**، یعنی دسترسی به فایل‌های محلی خاموش است:

```
chrome://extensions  →  روی کارت افزونه «Details»  →  «Allow access to file URLs» را روشن کن
```

بعد صفحه را `F5` کن. (این تیک پیش‌فرض خاموش است و فقط یک‌بار باید زده شود.)

### راه دوم — با سرور محلی

اگر ترجیح می‌دهی از `http://` استفاده کنی:

```bash
npm run sim
```

```
http://127.0.0.1:8099/
```

⚠️ **این فقط وقتی کار می‌کند که سرور روی همین کامپیوتر تو باشد.** سرور روی ماشین من بالا می‌آید، پس
`127.0.0.1:8099` از کامپیوتر تو به ماشین من اشاره می‌کند و چیزی باز نمی‌شود. برای استفاده از این راه، ریپو را
روی سیستم خودت داشته باش.

## صفحه چه دارد

**ساعت زنده** بالای صفحه با صدم ثانیه — مرجع مقایسه:

```
15:52:10:02
```

**چهار نقطهٔ مجزا** (۱ تا ۴). هر کدام با کلیک:
- شمارندهٔ خودش بالا می‌رود
- **زمان دقیق کلیک** را نشان می‌دهد: `15:52:10:02`
- یک قاب سبز می‌زند

**سه دکمهٔ هم‌نام** — همه با متن `ارسال پی در پی سفارش` — برای تست گزینهٔ **«همهٔ تطابق‌ها»**.

**جدول ثبت** پایین صفحه: شماره، زمان با صدم ثانیه، هدف، و **فاصله از کلیک قبلی به میلی‌ثانیه**.

---

## سه کاری که می‌توانی تست کنی

### ۱. تست Pick

```
۱. در افزونه گام CLICK بساز
۲. روی ⌖ Pick بزن
۳. روی نقطهٔ ۲ کلیک کن
۴. افزونه برمی‌گردد و سلکتور پر می‌شود
۵. Run now
۶. ببین نقطهٔ ۲ سبز شد و زمانش ثبت شد
```

**و حالا می‌توانی اصلاحش کنی:** سلکتور را دستی عوض کن (زنجیرهٔ fallback حذف می‌شود)، یا `✕` بزن تا کلاً پاک شود.

### ۲. چند نقطه با هم

سه گام CLICK بساز، هر کدام روی یک نقطه. یک Run — هر سه با زمان خودشان ثبت می‌شوند:

```
1  15:52:10:60   نقطه ۴   +0ms
2  15:52:10:61   نقطه ۱   +10ms
3  15:52:10:63   نقطه ۳   +21ms
```

فاصلهٔ ۱۰-۲۰ میلی‌ثانیه بین گام‌ها طبیعی است (رفت‌وبرگشت پیام).

### ۳. «همهٔ تطابق‌ها»

یک گام CLICK با `Find: text` و متن `ارسال پی در پی سفارش`، و تیک **«همهٔ تطابق‌ها»**.

درست = هر سه یک‌بار:
```
همنام ۳   →   همنام ۲   →   همنام ۱
```

---

## 🔴 باگی که همین صفحه پیدا کرد

اولین نسخهٔ «همه را بزن» **۱۵۹ بار همان دکمهٔ سوم** را زد تا اجرا با timeout مرد.

**چرا:** منطقش به **موقعیت** تکیه داشت — «آخرینِ باقی‌مانده». روی fixture قبلی هر دکمه **خودش را حذف می‌کرد**، پس لیست کوتاه می‌شد و «آخرین» عوض می‌شد. این صفحه دکمه‌ها را **نگه می‌دارد** (مثل یک صفحهٔ سفارش واقعی) ⇒ «آخرین» همیشه همان یکی.

**رفع:** حالا **هویت** عنصر ردیابی می‌شود (`WeakSet`)، نه موقعیت.

**و درس واقعی:** تستی که صفحه‌اش **کمک می‌کند**، باگی را پنهان می‌کند که صفحهٔ واقعی نشان می‌دهد. حالا هر دو شکل تست می‌شوند.

## 🪟 پنجرهٔ شناور سفارش — مدل‌شده از سامانهٔ واقعی

صفحه حالا **فهرست نمادها** دارد. روی هر ردیف کلیک کن تا یک **پنجرهٔ شناور سفارش** باز شود، مثل سامانهٔ معاملات:

```
┌──────────────────────────────────┐
│ [خرید] [فروش]              [✕]   │  ← نوار عنوان: هم تب‌ها، هم دستگیرهٔ جابه‌جایی
├──────────────────────────────────┤
│ فزر    334,300    +2.99%         │
│ قیمت   [334300]  [▼]             │
│ تعداد   [3000]  [+][−]           │
│ دارایی  0                        │
│ سرمایه  0                        │
│ اعتبار   0                        │
│ [   خرید   ]  [   فروش   ]       │
└──────────────────────────────────┘
```

**نوار عنوان را بگیر و بکش** — پنجره جابه‌جا می‌شود. این همان چیزی است که تستش می‌خواستی.

### جدول ثبت حالا ستون «نماد» دارد

```
#   زمان          هدف          نماد    رویداد           فاصله
3   21:24:13:89   دکمهٔ خرید   فزر     خرید             61
```

**این ستون مهم‌ترین اضافه است:** اگر کلیک روی پنجرهٔ **اشتباه** برود، از اینجا می‌بینی — چون نماد ثبت‌شده با نمادی که می‌خواستی فرق می‌کند. قبلاً هر دو کلیک یکسان دیده می‌شدند.

### کلید «پنجره‌ها نشانهٔ نماد داشته باشند»

بالای صفحه یک تیک هست:

- **تیک روشن (پیش‌فرض)** — پنجره‌ها `data-symbol` دارند، مثل سامانهٔ واقعی. سلکتور **لنگر می‌شود** و جابه‌جایی امن است.
- **تیک خاموش** — پنجره‌ها **هیچ نشانه‌ای** ندارند. این حالت برای دیدن هشدار **⚠ موقعیتی** در پنل است: آن‌وقت هیچ سلکتوری نمی‌تواند پنجره‌ها را از هم تشخیص دهد.

### سه چیزی که با پنجره‌ها می‌توانی تست کنی

**۱. جابه‌جایی امن** — Pick روی دکمهٔ خرید پنجرهٔ فزر → پنجره را بکش جای دیگر → یک پنجرهٔ دیگر جای قبلی‌اش باز کن → Run. باید روی **فزر** کلیک شود.

**۲. هشدار موقعیتی** — تیک «نشانهٔ نماد» را بردار، Pick بزن. در پنل کنار سلکتور **⚠** می‌بینی.

**۳. چند پنجره، چند نقطه** — دو پنجره باز کن، از هر کدام یک دکمه Pick کن و در دو گام جدا کلیک کن. در جدول، هر کلیک با نماد خودش ثبت می‌شود.

## محدودیت‌ها — صادقانه

| چیز | وضعیت |
|---|---|
| تعویض تب / فوکوس | روی این صفحه تست نمی‌شود (تب ساده است) |
| تأخیر شبکه | صفحه محلی است، شبکه ندارد. برای تست کندی، یک `Wait` بگذار |
| تأیید دوم (رمز/کد) | شبیه‌سازی نشده |
| تأخیر شبکه در ثبت سفارش | صفحه محلی است؛ برای تست کندی یک `Wait` بگذار |
| تأیید نهایی سفارش | شبیه‌سازی نشده — صفحه فقط ثبت می‌کند که کلیک شد، نه اینکه سفارش پذیرفته شد |
| زمان‌بندی ساعت | قابل تست است: ساعت را روی چند ثانیهٔ بعد بگذار و ببین چه زمانی ثبت می‌شود |

## 🔴 باگ دوم: پنج زمان‌بندی روی یک ثانیه — دو تایش اجرا نمی‌شد

**نشانه:** از پنج مورد، دو تا موقع رسیدن زمان ثبت نشدند.

**علت اول — نه همزمانی، بلکه «یک اسلات»:** `activeRun` یک متغیر تک‌مونه است. هر پنج آلارم با هم می‌رسند، اولی
اسلات را می‌گیرد، و بقیه با `a run is already in progress` **رد** می‌شدند. و بدتر: آن رد شدن به‌عنوان یک اجرا با
`reason: step-error` ثبت می‌شد — یعنی **اجرایی که هرگز اتفاق نیفتاد، شبیه اجرایی که شکست خورد دیده می‌شد**.

**علت دوم — آلارم دیر:** اگر سیستم خواب رفته باشد یا مرورگر مشغول باشد، آلارم بعد از هدف می‌رسد. کد قدیم
وقوع بعدی برنامه را «فردا» می‌دید و اجرا را **بی‌صدا دور می‌ریخت**.

**چرا «۵ میلی‌ثانیه بین کلیک‌ها» جواب نمی‌داد:** اجراهای قبلی همچنان در حال انتظار برای همان لحظهٔ دقیق‌اند؛
با تمام شدن گام، انتظارشان تمام نمی‌شود. باید **صف** می‌شد، نه پخش در میلی‌ثانیه‌ها.

**رفع:**
- اجرای زمان‌بندی‌شده اگر اسلات مشغول باشد **منتظر می‌ماند** (تا ۲۰ ثانیه) و بعد اجرا می‌شود. ترتیب حفظ می‌شود و
  هیچ‌چیز دور ریخته نمی‌شود.
- اگر آلارم تا **۱۰ ثانیه** دیر رسیده باشد، همچنان اجرا می‌شود و تأخیرش در کنسول ثبت می‌شود. بیشتر از آن، به‌عنوان
  «از دست رفته» ثبت می‌شود نه اینکه بی‌صدا اجرا شود.

**سنجیده شد:** `scripts/multi-schedule-test.mjs` — پنج اتوماسیون روی یک ثانیه، پنج نقطهٔ مختلف:
**۵/۵ کلیک، پنج رکورد `finished`، صفر رد شدن.**
