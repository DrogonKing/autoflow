# بورس کالا — راهنمای پنل

نگاشت هر فیلد پنل به مقداری که برای بورس کالا باید بگذاری. نام فیلد **انگلیسی** نوشته شده تا در پنل پیدایش کنی، حتی اگر زبان پنل فارسی باشد.

> **وضعیت صادقانه:** این نگاشت از روی **رفتار افزونه** نوشته شده، نه از روی اجرای واقعی روی سامانهٔ بورس کالا. من به آن سامانه دسترسی ندارم. جاهایی که مطمئن نیستم با 🔶 علامت زده‌ام و باید با یک **پروفایل تمرینی** (پایین) تست شود.

---

## ۱. `TIMER` — زمان‌بندی

| فیلد | مقدار برای بورس کالا | چرا |
|---|---|---|
| `When` | `daily` | هر روز ساعت مشخص |
| `Time` | **`09:00`** — نه `00:00` | پیش‌فرض `00:00` است که برای بورس بی‌فایده است |
| `Today only` | **تیک بزن** ☑ | پایین توضیح داده شده |
| `Next runs` | باید سه تاریخ **امروز/فردا/پس‌فردا ۰۹:۰۰** نشان دهد | اگر `00:00` دیدی، `Time` را عوض نکرده‌ای |

### چرا «Today only» حیاتی است

```
برنامه‌ات ۰۹:۰۰ است و ساعت ۰۹:۰۰:۰۵ روشنش می‌کنی:

☐ بدون تیک  →  «فردا ۰۹:۰۰»        ← یک روز کامل دیر!
☑ با تیک    →  «امروز دیگر اجرا نمی‌شود»  ← صریح
```

برای پنجرهٔ سفارش **تیک بزن**. اگر تیک نزنی، یک روز دیر میشود و تو فکر میکنی کار میکند.

### `cron` با ثانیه — اگر پنجره ثانیه‌ای است

cron پنج‌فیلدی فقط تا **دقیقه** دقت دارد. اگر باید در ثانیهٔ دقیق بزنی، **شش‌فیلدی** بده:

```
0 9 * * 1-5        →  09:00:00   (دقیقه — معمولاً این کافی است)
0 0 9 * * 1-5      →  09:00:00   ثانیهٔ دقیق (ss mm hh day month weekday)
```

## ۲. `STEPS` — گام‌ها

### گام اول: `Click`

| فیلد | مقدار |
|---|---|
| `Find` | 🔶 **`css` یا `text`** — بستگی به صفحه دارد |
| `selector, path or text` | 🔶 سلکتور دکمهٔ خرید |
| `Button` | `left` |
| `Clicks` | `1` |
| `Delay` | **`0`** — خالی بگذار |
| `Retries` | **`2`** |
| `On error` | **`stop the run`** |

**چرا `Delay` صفر:** تأخیر بین گام‌ها جای دیگری است (Step delay، پیش‌فرض ۱۲۰ms). `Delay` اینجا فقط قبل از همین گام صبر میکند. و یادت باشد **`Delay` سرعت کلیک را تعیین نمی‌کند** — آن سقف ~۶ms معماری است.

**چرا `retries: 2`:** دکمه ممکن است با تأخیر فعال شود. دو تلاش دوباره ارزان است.

### 🔴 گام دوم **اجباری**: `Wait for`

```
Find:     text
text:     متن تأیید سفارش   ← 🔶 دقیقاً چه متنی؟
Timeout:  15000
```

**بدون این گام نمیدانی سفارش پذیرفته شد یا نه.** «کلیک شد» ≠ «سفارش ثبت شد». اگر گام اول بیصدا شکست بخورد، بدون گام دوم فکر میکنی موفق شدی.

**پیشنهاد:** با پروفایل تمرینی (پایین) اول ببین بعد از خرید **چه متنی** ظاهر میشود، بعد همان را اینجا بگذار.

---

## ۳. ⚠️ ده دکمهٔ هم‌نام — «ارسال پی در پی سفارش»

**اگر ده تا از این دکمه در صفحه باشد، یک گام `Click` فقط یکی را میزند و می‌ایستد.**

در کد: `findElement` برمیگرداند `chosen[finder.index ?? 0]` — یعنی **`index: 0`، اولین در DOM** (که با «اولین بصری» یکی نیست).

### راه درست: حلقه روی همه

```
گام ۱:  ACTIONS → Extract
        Find:  css
        selector:  دکمه‌های «ارسال پی در پی سفارش»     ← 🔶
        Into:  buttons

گام ۲:  ACTIONS → Loop
        List:  buttons
        └─ Click   روی همین یکی
        └─ Wait for   متن تأیید
```

⚠️ **صادقانه:** `extract` الان **متن** برمیگرداند نه عنصر، پس این الگو **باید اول تست شود** که آیا لیست عناصر قابل پیمایش است. اگر نشد، باید قابلیت «برای هر تطابق» اضافه شود — که در حال ساخت است.

---

## ۴. 🔶 ناشناخته‌ها — که فقط با تست روشن می‌شوند

این‌ها را **نمیدانم** و حدس نمیزنم:

| سؤال | چطور روشن می‌شود |
|---|---|
| سلکتور دقیق دکمهٔ خرید چیست؟ | اسکرین‌شات صفحه، یا `Pick` روی خودش |
| بعد از خرید چه متنی می‌آید؟ | پروفایل تمرینی، اجرا، خواندن History |
| صفحه چقدر طول می‌کشد تا دکمه فعال شود؟ | پروفایل تمرینی + یک `Wait for` قبل از کلیک |
| «ارسال پی در پی سفارش» همه را میزند یا یکی؟ | 🔶 **خود سامانه تعیین می‌کند** — نه افزونه |
| آیا تأیید دوم (کد پیامکی/رمز) لازم است؟ | پروفایل تمرینی نشان می‌دهد |

---

## ۵. ✅ پروفایل تمرینی — **هیچ کلیکی نمیکند**

این را بساز و روی صفحهٔ بورس کالا اجرا کن. **دکمهٔ خرید را نمیزند** — فقط نگاه میکند و میگوید چه میبیند.

```
گام ۱:  ACTIONS → Wait
        ms:  3000

گام ۲:  ACTIONS → Wait for
        Find:     css
        selector: body
        Timeout:  10000
        (یعنی: صبر کن صفحه بیاید)

گام ۳:  ACTIONS → Extract
        Find:     css
        selector: button
        Into:     allButtons

گام ۴:  ACTIONS → Extract
        Find:     css
        selector: input
        Into:     allInputs

گام ۵:  ACTIONS → Notify
        message:  بررسی تمام شد — History را ببین
```

بعد **History** را باز کن و ببین چه استخراج شد.

**بعد اسکرین‌شات این دو را بفرست:**
1. صفحهٔ بورس کالا، جایی که دکمهٔ خرید هست
2. تب History بعد از اجرای پروفایل تمرینی

از این دو، سلکتور دقیق و متن تأیید را مینویسم و پروفایل واقعی را میسازم.

## ۶. جدول نهایی — هر فیلد و مقدارش

| فیلد پنل (انگلیسی) | فیلد پنل (فارسی) | مقدار برای بورس کالا |
|---|---|---|
| `Find` | روش یافتن | `css` یا `text` 🔶 |
| `Button` | دکمهٔ ماوس | `left` |
| `Clicks` | تعداد کلیک | `1` |
| `Delay` | تأخیر | `0` (خالی) |
| `Retries` | تلاش دوباره | `2` |
| `On error` | اگر خطا داد | `stop the run` / «کل اجرا بایستد» |
| `Time` | ساعت | `09:00` (نه `00:00`) |
| `Today only` | فقط امروز | **تیک** ☑ |
| `Step delay` | فاصلهٔ بین گام‌ها | `120` (پیش‌فرض) |
| `Timeout` (در Wait for) | مهلت | `15000` |

## ۷. و چیزهایی که **نمیتوانی** از افزونه بخواهی

صریح میگویم تا وقت تلف نشود:

| خواسته | واقعیت |
|---|---|
| سبقت از سرور کارگزار | ❌ کلاینت نمیتواند از سرور-ساید جلو بزند |
| زیر ۶ms بین کلیک‌ها | ❌ سقف معماری است |
| دو گام همزمان | ❌ یکی یکی اجرا می‌شوند |
| کلیک روی دکمهٔ غیرفعال | ❌ افزونه نمیتواند دکمه‌ای که سایت غیرفعال کرده را فعال کند |

**اگر کارگزار API دارد، بپرس.** افزونه سریع‌ترین گزینه **وقتی API نباشد** است.
